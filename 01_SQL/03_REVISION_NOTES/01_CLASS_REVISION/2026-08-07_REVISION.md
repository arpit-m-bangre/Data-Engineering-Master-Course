## STEP 1 — QUICK RECALL

### Recall Questions
1. In what exact sequence does SQL Server process `WHERE`, `HAVING`, `FROM`, `ORDER BY`, `GROUP BY`, and `SELECT`?
2. Why can't you use `WHERE AVG(marks) > 75` to filter average marks?
3. Why does `HAVING total_salary > 2000` fail when `total_salary` is aliased in `SELECT`?
4. Does `WHERE` filter individual rows or grouped aggregate results?

### Answers & Explanations
1. **Execution Order**:
   - Step 1: `FROM` (Identify table source)
   - Step 2: `WHERE` (Filter individual raw rows)
   - Step 3: `GROUP BY` (Group remaining rows)
   - Step 4: `HAVING` (Filter grouped aggregate results)
   - Step 5: `SELECT` (Project output columns & evaluate aliases)
   - Step 6: `ORDER BY` (Sort final output result set)
2. **`WHERE` vs `HAVING`**: `WHERE` runs *before* grouping occurs, so aggregate functions like `AVG()` do not exist yet. You must use `HAVING` for aggregate conditions.
3. **Alias Scoping**: `HAVING` executes *before* `SELECT`. The alias `total_salary` is created in `SELECT`, so `HAVING` does not recognize it yet.
4. **`WHERE` Scope**: `WHERE` filters individual raw rows; `HAVING` filters aggregated groups.

## STEP 2 — CONCEPT UNDERSTANDING

### Topic 1: Memory Rule — WHERE vs HAVING
```
WHERE   -> Filters ROWS (Executes BEFORE GROUP BY)
HAVING  -> Filters GROUPS (Executes AFTER GROUP BY)
```

### Topic 2: Multi-Clause Scenario Strategy
When solving complex word problems, write your query in **Execution Order**:
1. `FROM`: Identify data source tables.
2. `WHERE`: Apply row-level conditions (`marks > 35`, `name LIKE '%r%'`).
3. `GROUP BY`: Define grouping column (`GROUP BY sub`).
4. `HAVING`: Apply aggregate filters (`HAVING AVG(marks) < 50 AND COUNT(id) > 5`).
5. `SELECT`: Specify projection columns and aliases (`sub, AVG(marks) AS avg_marks`).
6. `ORDER BY`: Apply sorting (`ORDER BY avg_marks DESC`).

## STEP 3 — SQL SYNTAX & CODE EXAMPLES

```sql
-- 1. Full 6-Clause Query
SELECT sub, 
       AVG(marks) AS avg_marks, 
       COUNT(id)  AS student_count
FROM student_dumy2
WHERE marks > 35 AND name LIKE '%r%'
GROUP BY sub
HAVING AVG(marks) < 50 AND COUNT(id) > 5
ORDER BY avg_marks ASC;

-- 2. ORDER BY Alias Usage
SELECT dept, SUM(salary) AS total_sal
FROM emp
GROUP BY dept
ORDER BY total_sal DESC; -- Alias 'total_sal' IS VALID in ORDER BY!
```

## STEP 4 — CONNECTION WITH PREVIOUS TOPICS

### Connecting Day 7 (`HAVING` & `ORDER BY`) + Days 2 & 6 (`WHERE` & Aggregates)
`HAVING` filters aggregate functions introduced in Day 6 (`SUM`, `AVG`, `COUNT`), while `WHERE` uses Day 2 relational logic (`LIKE`, `IN`, `BETWEEN`).

```sql
-- Day 2 (WHERE) + Day 6 (Aggregates) + Day 7 (HAVING & ORDER BY)

FROM emp
WHERE dept IS NOT NULL AND empname LIKE '%a%' -- Day 2 WHERE
GROUP BY dept                                -- Day 6 Grouping
HAVING SUM(salary) > 2000                     -- Day 7 HAVING
ORDER BY total_sal DESC;                     -- Day 7 ORDER BY
```

## STEP 5 — COMMON MISTAKES & DEBUGGING

### Buggy Query 1
```sql
-- Bug: Using column alias in HAVING clause
SELECT dept, SUM(salary) AS total_salary
FROM emp
GROUP BY dept
HAVING total_salary > 2000;
```
- **Correction**: Replace alias `total_salary` with the raw aggregate function `SUM(salary)`.
```sql
SELECT dept, SUM(salary) AS total_salary
FROM emp
GROUP BY dept
HAVING SUM(salary) > 2000;
```

**Scenario**: E-commerce reporting pipeline auditing sales performance for high-value items.
- **Required Info**: Total department revenue for orders > $1,000 joined after 2020 where department total > $300,000.

## STEP 7 — MINI ASSESSMENT

### Questions
1. What is the execution order of `SELECT`, `WHERE`, `FROM`, `GROUP BY`, `HAVING`, `ORDER BY`?
2. Write a query to find department-wise employee counts for departments having more than 5 employees, sorted by employee count descending.
3. Why is an alias allowed in `ORDER BY` but not in `HAVING`?

### Solutions
```sql
-- 1. Order: FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY

-- 2. Query Solution
SELECT dept, COUNT(empid) AS emp_cnt
FROM emp
GROUP BY dept
HAVING COUNT(empid) > 5
ORDER BY emp_cnt DESC;

-- 3. Explanation: Because ORDER BY executes AFTER SELECT (when aliases exist), whereas HAVING executes BEFORE SELECT.
```
