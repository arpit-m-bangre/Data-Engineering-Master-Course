## STEP 1 — QUICK RECALL

### Recall Questions
1. Does the `<>` (Not Equal) operator evaluate `NULL` values as true?
2. What is the difference between `%` and `_` in `LIKE` pattern matching?
3. How does `BETWEEN 2000 AND 6000` handle range boundaries (inclusive or exclusive)?
4. What wildcard pattern matches any string starting with letters A through M?

### Answers & Explanations
1. **`<>` and `NULL`**: No. Relational operators (`=`, `<>`) evaluate `NULL` comparisons as `UNKNOWN`. To filter `NULL` values, you must explicitly use `IS NULL` or `IS NOT NULL`.
2. **Wildcards**: `%` matches **zero or more characters** of any length; `_` matches **exactly one single character**.
3. **`BETWEEN` Boundaries**: `BETWEEN` is **inclusive** of both boundary values (e.g. 2000 and 6000 are included in the output).
4. **Range Wildcard**: `LIKE '[A-M]%'`.

## STEP 2 — CONCEPT UNDERSTANDING

### Topic 1: The `WHERE` Clause
- **What it means**: A row-level filter applied directly to source tables before any grouping or aggregation occurs.
- **Why/When used**: Used whenever you need to retrieve, update, or delete specific rows matching explicit criteria.

### Topic 2: Logical Operators — `AND` vs `OR`
- **What it means**:
  - `AND`: All combined conditions must evaluate to TRUE for a row to be included.
  - `OR`: At least one condition must evaluate to TRUE for a row to be included.

### Topic 3: `LIKE` Pattern Matching & Wildcards
- **Wildcard Cheat Sheet**:
  - `'A%'`: Starts with A.
  - `'%h'`: Ends with h.
  - `'%A%'`: Contains A anywhere.
  - `'R%A'`: Starts with R and ends with A.
  - `'_m%'`: Second character is m.
  - `'[A,M]%'`: Starts with either A or M.
  - `'[A-Z]%'`: Starts with any letter A through Z.
  - `'[^A-Z]%'`: Does NOT start with a letter A through Z.

## STEP 3 — SQL SYNTAX & CODE EXAMPLES

```sql
-- 1. Comparison & Nullability
SELECT * FROM employee1 WHERE dept = 'HR';
SELECT * FROM employee1 WHERE dept <> 'HR';
SELECT * FROM employee1 WHERE dept IS NULL;

-- 2. IN and BETWEEN
SELECT * FROM employee1 WHERE dept IN ('HR', 'Entc');
SELECT * FROM employee1 WHERE salary BETWEEN 2000 AND 6000;

-- 3. LIKE Patterns
SELECT * FROM employee1 WHERE empname LIKE 'A%';
SELECT * FROM employee1 WHERE empname LIKE '_m%';
SELECT * FROM employee1 WHERE empname LIKE '[^A-Z]%';
```

## STEP 5 — COMMON MISTAKES & DEBUGGING

### Buggy Query 1
```sql
-- Bug: Using = NULL instead of IS NULL
SELECT * FROM employee1 WHERE dept = NULL;
```
- **Correction**: `dept = NULL` will return 0 rows because `NULL` cannot be compared with `=`. Use `IS NULL`.
```sql
SELECT * FROM employee1 WHERE dept IS NULL;
```

### Buggy Query 2
```sql
-- Bug: Forgetting quotes around string in BETWEEN
SELECT * FROM employee1 WHERE empname BETWEEN A AND M;
```
- **Correction**: Character bounds must be enclosed in single quotes `'A'` and `'M'`.
```sql
SELECT * FROM employee1 WHERE empname BETWEEN 'A' AND 'M';
```

## STEP 6 — REAL-WORLD DATA ENGINEERING APPLICATION

**Scenario**: A fraud detection engine parses incoming transaction logs to flag suspicious withdrawals.
- **Required Info**: Withdrawals exceeding $5,000 made outside the user's registered home city.
- **SQL Approach**: Combine `WHERE` clause relational checks with `AND`/`OR` logic:
```sql
SELECT * FROM Transactions 
WHERE TransactionAmount > 5000 
  AND TransactionCity <> RegisteredHomeCity;
```
