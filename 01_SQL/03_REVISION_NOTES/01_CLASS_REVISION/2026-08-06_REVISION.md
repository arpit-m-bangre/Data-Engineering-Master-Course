## TODAY'S TOPICS
- **5 Core Aggregate Functions**: `MIN()`, `MAX()`, `SUM()`, `AVG()`, `COUNT()`
- **Data Type Constraints**: `SUM()` and `AVG()` require numeric data types (`INT`, `FLOAT`, `DECIMAL`).
- **`NULL` Behavior**: Aggregate functions ignore `NULL` values (`AVG` divides by non-NULL count; `COUNT(col)` ignores `NULL`; `COUNT(*)` counts all rows including `NULL`s).
- **`DISTINCT` Keyword**: Returning unique row combinations & `COUNT(DISTINCT col)`.
- **Result Limiting (`TOP N`)**: Returning the top N rows in SQL Server.
- **`GROUP BY` Basics**: Combining non-aggregated group columns with aggregate functions.

## STEP 1 — QUICK RECALL

### Recall Questions
1. Why does `SUM(empname)` fail with an error in SQL Server?
2. What is the difference between `COUNT(dept)` and `COUNT(*)` when a table contains `NULL` values in `dept`?
3. How does `AVG()` calculate average when one of the rows is `NULL`?
4. Can you use `SELECT *` alongside `AVG(salary)` without a `GROUP BY` clause?

### Answers & Explanations
1. **Data Type Rule**: `SUM()` and `AVG()` require numeric operand types (`INT`, `FLOAT`, `DECIMAL`). `VARCHAR` strings cannot be summed.
2. **`COUNT(col)` vs `COUNT(*)`**: `COUNT(dept)` counts non-NULL `dept` values; `COUNT(*)` counts all rows regardless of whether columns contain `NULL`.
3. **`AVG` and `NULL`**: `AVG()` completely ignores `NULL` rows in both the numerator (sum) and denominator (count). For example, values (20, 30, NULL, 30) give AVG = 80 / 3 = 26.66.
4. **`SELECT *` with Aggregates**: No. Aggregate functions collapse rows into a single summary output, so individual un-aggregated row columns (`SELECT *`) cannot be displayed alongside them without `GROUP BY`.

## STEP 2 — CONCEPT UNDERSTANDING

### Topic 1: The 5 Aggregate Functions

```
MIN(col)   -> Returns the lowest value in a column (works on numbers & strings)
MAX(col)   -> Returns the highest value in a column (works on numbers & strings)
SUM(col)   -> Returns total sum of numbers (numeric columns only)
AVG(col)   -> Returns average of numbers (numeric columns only, ignores NULL)
COUNT(col) -> Returns count of non-NULL values
COUNT(*)   -> Returns total row count of table
```

### Topic 2: `DISTINCT` Rules
- `DISTINCT` eliminates duplicate rows in the output projection.
- `DISTINCT` applies to **all columns selected together**, not individual columns separately.
- Invalid Syntax: `SELECT DISTINCT(col1), DISTINCT(col2) FROM table;` (Cannot use `DISTINCT` separately on multiple columns).

### Topic 3: `TOP N` Clause
- Returns the first $N$ rows from a query result set.
- Syntax: `SELECT TOP 3 salary FROM emp;`

## STEP 3 — SQL SYNTAX & CODE EXAMPLES

```sql
-- 1. Aggregations
SELECT MIN(salary) AS min_sal, MAX(salary) AS max_sal FROM emp;
SELECT AVG(salary) AS avg_sal, SUM(salary) AS total_sal FROM emp;

-- 2. COUNT vs COUNT(*) vs COUNT(DISTINCT)
SELECT COUNT(org_id) FROM emp;         -- Ignores NULLs
SELECT COUNT(*) FROM emp;              -- Includes NULLs
SELECT COUNT(DISTINCT org_id) FROM emp; -- Counts unique non-NULL org_ids

-- 3. TOP N Clause
SELECT TOP 2 * FROM emp;

-- 4. Basic GROUP BY
SELECT org_id, AVG(salary) AS avg_salary 
FROM emp 
GROUP BY org_id;
```

## STEP 5 — COMMON MISTAKES & DEBUGGING

### Buggy Query 1
```sql
-- Bug: Using SELECT * alongside an aggregate function
SELECT *, AVG(salary) FROM emp;
```
- **Correction**: You cannot select un-aggregated row columns `*` alongside a summary aggregate. Remove `*` or use `GROUP BY`.
```sql
SELECT AVG(salary) AS avg_salary FROM emp;
```

### Buggy Query 2
```sql
-- Bug: Using DISTINCT on multiple columns separately
SELECT DISTINCT(empname), DISTINCT(org_id) FROM emp;
```
- **Correction**: Apply `DISTINCT` once across the selected column list.
```sql
SELECT DISTINCT empname, org_id FROM emp;
```

## STEP 6 — REAL-WORLD DATA ENGINEERING APPLICATION

**Scenario**: Executive sales dashboard computing key performance metrics (KPIs) per region.
- **Required Info**: Total revenue, average order size, total order count, and unique customer count per sales region.
- **SQL Approach**: Use `GROUP BY` with multiple aggregate functions:
```sql
SELECT Region,
       SUM(OrderAmount) AS TotalRevenue,
       AVG(OrderAmount) AS AvgOrderSize,
       COUNT(OrderID)   AS TotalOrders,
       COUNT(DISTINCT CustomerID) AS UniqueCustomers
FROM SalesOrders
GROUP BY Region;
```
