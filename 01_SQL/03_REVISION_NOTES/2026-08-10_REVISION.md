## TODAY'S TOPICS
- **Data Validation vs Constraints**: Constraints are engine-level SQL rules enforcing data validation.
- **PRIMARY KEY**: Uniquely identifies each row (Rules: Unique, NO `NULL`, max 1 per table).
- **UNIQUE**: Prevents duplicate values (Rules: Unique, allows a single `NULL` once).
- **NOT NULL**: Disallows `NULL` entries (Duplicates allowed).
- **CHECK Constraint**: Enforces custom boolean expressions (`Age > 18`, `Name NOT LIKE 'a%'`, `Grade IN ('A','B')`).
- **Keys Management**: Inspecting constraints in SSMS Object Explorer $\rightarrow$ Table $\rightarrow$ Keys.

## STEP 1 — QUICK RECALL

### Recall Questions
1. How many Primary Keys can exist in a single SQL table?
2. What is the fundamental difference between `PRIMARY KEY` and `UNIQUE` constraint regarding `NULL` handling?
3. How can you combine constraints to create an alternative to a Primary Key on another column?
4. What error message is raised when inserting an age of 16 into a column defined with `CHECK (Age > 18)`?

### Answers & Explanations
1. **Primary Key Limit**: Exactly **one** Primary Key per table.
2. **`PK` vs `UNIQUE` `NULL` Handling**: A `PRIMARY KEY` does NOT allow `NULL` values at all. A `UNIQUE` constraint allows **one single `NULL` value**.
3. **Alternative PK Pattern**: Combine `NOT NULL` and `UNIQUE` on the target column (`custid INT NOT NULL UNIQUE`).
4. **CHECK Error**: "The INSERT statement conflicted with the CHECK constraint..."

## STEP 2 — CONCEPT UNDERSTANDING

### Constraint Matrix Cheat Sheet

| Constraint | Uniqueness | Allows NULL? | Max Per Table |
| :--- | :--- | :--- | :--- |
| **`PRIMARY KEY`** | Must be unique | NO (Disallowed) | 1 per table |
| **`UNIQUE`** | Must be unique | YES (Single `NULL` once) | Multiple allowed |
| **`NOT NULL`** | Duplicates allowed | NO (Disallowed) | Multiple allowed |
| **`CHECK`** | Depends on rule | YES (unless combined with `NOT NULL`) | Multiple allowed |

## STEP 3 — SQL SYNTAX & CODE EXAMPLES

```sql
-- 1. PRIMARY KEY
CREATE TABLE Q1 (
    id   INT PRIMARY KEY,
    name VARCHAR(10)
);

-- 2. UNIQUE & NOT NULL Combined
CREATE TABLE Q3 (
    id     INT PRIMARY KEY,
    f_name VARCHAR(10) NOT NULL,
    custid INT NOT NULL UNIQUE
);

-- 3. CHECK Constraint (Multiple Conditions)
CREATE TABLE Q4 (
    id   INT,
    age  INT CHECK (age > 18),
    name VARCHAR(10) CHECK (name NOT LIKE 'a%'),
    grade VARCHAR(10) CHECK (grade IN ('A', 'B', 'C'))
);

-- 4. Adding CHECK Constraint via ALTER TABLE
ALTER TABLE Q4
ADD marks INT CHECK (marks NOT LIKE '9%' AND marks <> 99234235);
```

## STEP 5 — COMMON MISTAKES & DEBUGGING

### Buggy Insertion 1
```sql
-- Bug: Attempting to insert a duplicate key into PRIMARY KEY column
INSERT INTO Q1 VALUES (1, 'a');
INSERT INTO Q1 VALUES (1, 'b'); -- Error!
```
- **Error**: Violation of PRIMARY KEY constraint. Cannot insert duplicate key in object 'dbo.Q1'.

### Buggy Insertion 2
```sql
-- Bug: Attempting to insert a second NULL into UNIQUE column
INSERT INTO Q2 VALUES (NULL, 'mumbai');
INSERT INTO Q2 VALUES (NULL, 'pune'); -- Error!
```
- **Error**: Violation of UNIQUE KEY constraint. Cannot insert duplicate key in object 'dbo.Q2'. (Unique constraint permits NULL only once).

## STEP 6 — REAL-WORLD DATA ENGINEERING APPLICATION

**Scenario**: Customer onboarding portal ingesting user registrations.
- **Validation Rules**:
  - `AccountID`: Must be unique and non-null (`PRIMARY KEY`).
  - `Email`: Must be unique (`NOT NULL UNIQUE`).
  - `Age`: Must be 18 or older (`CHECK (Age >= 18)`).
- **SQL Approach**: Define constraints directly in database tables so invalid records are rejected automatically by the database engine.
