## 1. What Did We Learn Today? (Topic Summary)

In today's class (17 August 2026), we mastered temporal data processing in SQL Server (T-SQL). We explored how dates and timestamps are stored, how to extract individual calendar components, how to calculate date differences across intervals, how to shift dates forward or backward, and how to detect the last day of any month.

### Core Functions Covered:
1. **`GETDATE()`** — Fetches the current system clock date and timestamp down to milliseconds (`YYYY-MM-DD HH:MM:SS.mmm`).
2. **`DATEDIFF(interval, start_date, end_date)`** — Calculates the number of interval boundaries crossed between two dates.
3. **`DATEPART(interval, target_date)`** — Extracts a specific numerical component (Year, Quarter, Month, Weekday, Hour, etc.).
4. **`DATEADD(interval, number, target_date)`** — Adds or subtracts a specific time interval to/from a date.
5. **`EOMONTH(target_date [, months_to_add])`** — Finds the exact ending date of the month (handles leap years automatically).

---

## 2. Why Does It Matter? (Enterprise & Interview Relevance)

In modern enterprise Data Engineering pipelines, **almost every business question is time-bound**:
- **E-Commerce & Retail:** Calculating Customer Churn (e.g., *"Find all users who haven't placed an order in the last 90 days"*).
- **Banking & Insurance:** Scheduling recurring EMI deductions and policy maturity alerts (e.g., `DATEADD(MM, 6, PolicyStartDate)`).
- **Healthcare & Hospital Operations:** Calculating Length of Stay (LOS) or patient wait times (e.g., `DATEDIFF(HH, AdmissionDate, DischargeDate)`).
- **Financial Reporting:** Aggregating metrics by fiscal quarter (`DATEPART(QQ, TransactionDate)`) and month-end closing balances (`EOMONTH(ReportDate)`).

### 🛠️ Core Syntax Blocks

```sql
-- 1. Get Current System Timestamp
SELECT GETDATE() AS CurrentTimestamp;

-- 2. Measure Difference Between Two Dates (start -> end)
SELECT DATEDIFF(MM, '2024-01-15', GETDATE()) AS MonthsElapsed;

-- 3. Extract Specific Date Part
SELECT DATEPART(WEEKDAY, GETDATE()) AS DayOfWeekNumber; -- 1=Sun, 2=Mon, ..., 7=Sat

-- 4. Shift Date Forward / Backward
SELECT DATEADD(MM, 6, GETDATE())  AS SixMonthsFuture;
SELECT DATEADD(DAY, -30, GETDATE()) AS ThirtyDaysAgo;

-- 5. Get Last Day of Current Month
SELECT EOMONTH(GETDATE()) AS LastDayOfCurrentMonth;
```

## 5. Common Mistakes & Bug Traps

### ⚠️ Trap 1: The Boundary Counting Illusion in `DATEDIFF`
* **The Bug:** `DATEDIFF(YEAR, '2025-12-31 23:59:59', '2026-01-01 00:00:01')` returns `1` year, even though only 2 seconds actually passed!
* **Why:** `DATEDIFF` counts boundary crossings (midnight on Dec 31 crossed to Jan 1), NOT continuous 365 days of elapsed time.

### ⚠️ Trap 2: Integer Overflow with `MS` (Milliseconds)
* **The Bug:** Running `DATEDIFF(MS, '2026-07-01', GETDATE())` causes `Msg 535: The datediff function resulted in an overflow`.
* **Why:** `DATEDIFF` returns a standard 4-byte `INT` (maximum value `2,147,483,647`). A gap of more than ~24.85 days in milliseconds exceeds this limit!
* **Fix:** Use `DATEDIFF_BIG(MS, start, end)` in modern SQL Server, or calculate in seconds (`SS`) or minutes (`N`).

### ⚠️ Trap 3: Region-Dependent Date Literal String Formats
* **The Bug:** Writing `'24/02/2026'` (UK/India DD/MM/YYYY) throws `Msg 241: Conversion failed when converting date and/or time from character string`.
* **Fix:** Always use ISO-8601 standard string literals (`'YYYY-MM-DD'`, e.g., `'2026-02-24'`) or standard US format (`'MM/DD/YYYY'`).

### ⚠️ Trap 4: Reversed Date Order producing Negative Numbers
* **The Rule:** Syntax is `DATEDIFF(interval, start_date, end_date)`.
* If `start_date` is later than `end_date`, SQL Server returns a **negative number**.

## 6. Vocabulary & Definitions

| Word | Simple Meaning in Plain English |
| :--- | :--- |
| **Temporal** | Anything related to time, dates, or calendar clocks. |
| **Interval / Datepart** | The unit of time measurement you choose (e.g., day, month, hour, quarter). |
| **Boundary** | The dividing line where one unit flips into the next (e.g., midnight flips from Tuesday to Wednesday). |
| **Overflow** | When a calculated number is too large to fit inside the memory box (data type) allocated for it. |
| **Literal** | A fixed value written directly into the query enclosed in quotes (e.g., `'2026-08-17'`). |
| **Precision** | How finely detailed the clock measurement is (e.g., seconds vs milliseconds). |

## 7. Quick Self-Quiz (Concept Checks)

### ❓ Q1: What does DATEDIFF(MM, '2026-01-31', '2026-02-01') return, and why?
> **Answer:** It returns **`1`**.
> **Reason:** Because `DATEDIFF` checks how many month boundaries were crossed. Jan 31 $\rightarrow$ Feb 1 crosses 1 month boundary, even though only 1 day has passed.

### ❓ Q2: Which SQL function and datepart would you use to filter employees who work on weekends?
> **Answer:** `WHERE DATEPART(WEEKDAY, JoiningDate) IN (1, 7)` (where `1 = Sunday` and `7 = Saturday`).

### ❓ Q3: How do you calculate a customer's subscription expiry date that lasts exactly 90 days from today?
> **Answer:** `SELECT DATEADD(DAY, 90, GETDATE()) AS ExpiryDate;`

### ❓ Q4: Why does EOMONTH('2024-02-10') return '2024-02-29' instead of '2024-02-28'?
> **Answer:** Because 2024 is a leap year (divisible by 4), and `EOMONTH` has built-in leap year calendar intelligence.
