## STEP 1 — QUICK RECALL

### Recall Questions
1. What data types support the `IDENTITY` property? Can you use `IDENTITY` on a `VARCHAR` column?
2. What is the fundamental requirement before you can define a `FOREIGN KEY` in a child table?
3. Can you delete a parent table row if a child table row currently references it?
4. Why does `TRUNCATE TABLE ParentTable` fail even if the child table is currently empty?

### Answers & Explanations
1. **`IDENTITY` Data Types**: `IDENTITY` requires **numeric integer types** (`INT`, `BIGINT`). It cannot be applied to `VARCHAR` or text columns.
2. **`FOREIGN KEY` Requirement**: To create a `FOREIGN KEY`, a corresponding `PRIMARY KEY` (or `UNIQUE` constraint) must exist on the referenced parent table.
3. **Parent Row Deletion**: No. SQL Server blocks deleting a parent row if active child records reference it ("FOREIGN KEY constraint conflict").
4. **`TRUNCATE` Protection**: `TRUNCATE` checks database object metadata definitions (structural references) rather than row counts. If a `FOREIGN KEY` points to a parent table, `TRUNCATE` is blocked entirely.

## STEP 2 — CONCEPT UNDERSTANDING

### Topic 1: 10 Data Insertion Patterns Cheat Sheet
1. `INSERT INTO t VALUES (v1, v2)` $\rightarrow$ All columns (sequence dependent).
2. `INSERT INTO t (c1) VALUES (v1)` $\rightarrow$ Column list (preferred production style).
3. `INSERT INTO t (c1, c2) VALUES (v1, v2)` $\rightarrow$ Multiple specific columns.
4. `INSERT INTO t VALUES (v1), (v2)` $\rightarrow$ Multi-row batch insertion.
5. `INSERT INTO t (c1) VALUES (v1), (v2)` $\rightarrow$ Multi-row specific columns.
6. `INSERT INTO t (c1) VALUES (v1)` $\rightarrow$ Omitted columns fallback to `DEFAULT`.
7. `INSERT INTO t VALUES (v1, DEFAULT)` $\rightarrow$ Explicit `DEFAULT` keyword.
8. `INSERT INTO t VALUES (v1, NULL)` $\rightarrow$ Explicit `NULL` insertion.
9. `INSERT INTO t SELECT c1, c2 FROM t2` $\rightarrow$ Copy data from another table.
10. `INSERT INTO t SELECT c1, c2 FROM t2 WHERE cond` $\rightarrow$ Conditional batch copy.

### Topic 2: Parent vs Child Table Rule Matrix

```
Parent / Referenced Table (Primary Key)
       ↓
  PRIMARY KEY
       ↑
  FOREIGN KEY
       ↓
Child / Referencing Table (Foreign Key)
```

| Operation | Child Table (Referencing) | Parent Table (Referenced) |
| :--- | :--- | :--- |
| **`DELETE` Row** | Allowed | Fails if referenced by child row |
| **`TRUNCATE` Table** | Allowed | NOT Allowed if referenced by FK constraint |
| **`DROP` Table** | Allowed | NOT Allowed while FK constraint exists |

## STEP 3 — SQL SYNTAX & CODE EXAMPLES

```sql
-- 1. DEFAULT Constraint
CREATE TABLE Q5 (
    id   INT,
    city VARCHAR(10) DEFAULT 'Pune'
);
INSERT INTO Q5 (id) VALUES (1); -- City becomes 'Pune'

-- 2. IDENTITY (Auto Increment)
CREATE TABLE Q7 (
    id   INT IDENTITY(1000, 1),
    name VARCHAR(10)
);
INSERT INTO Q7 VALUES ('a'), ('b'); -- Auto generates id 1000, 1001

-- 3. FOREIGN KEY Relationship
CREATE TABLE Q1 (
    PKID INT PRIMARY KEY,
    Name VARCHAR(10)
);

CREATE TABLE Q9 (
    Custid INT FOREIGN KEY REFERENCES Q1(PKID),
    Pid    INT,
    Amount INT
);
```

## STEP 5 — COMMON MISTAKES & DEBUGGING

### Buggy Insertion 1
```sql
-- Bug: Inserting FK value that does not exist in Parent PK column
INSERT INTO Q9 VALUES (99, 101, 70000); -- PKID 99 does NOT exist in Q1!
```
- **Error**: The INSERT statement conflicted with the FOREIGN KEY constraint. The conflict occurred in table "dbo.Q1", column 'PKID'.

### Buggy Deletion 2
```sql
-- Bug: Attempting to DROP parent table while child table exists
DROP TABLE Q1;
```
- **Error**: Could not drop object 'q1' because it is referenced by a FOREIGN KEY constraint. Must drop child table `Q9` first!

## STEP 7 — MINI ASSESSMENT

### Questions
1. Create a parent table `Category` (`CategoryID` INT PRIMARY KEY) and child table `Product` (`ProductID` INT PRIMARY KEY, `CategoryID` INT FOREIGN KEY REFERENCES Category(CategoryID)).
2. Can you truncate table `Category` while table `Product` references it?
3. Which table must be dropped first: `Category` or `Product`?

### Solutions
```sql
-- 1. Table Definitions
CREATE TABLE Category (CategoryID INT PRIMARY KEY);
CREATE TABLE Product (
    ProductID INT PRIMARY KEY,
    CategoryID INT FOREIGN KEY REFERENCES Category(CategoryID)
);

-- 2. Answer: No. TRUNCATE TABLE Category will fail due to Foreign Key reference.
-- 3. Answer: Child table `Product` must be dropped first.
```
