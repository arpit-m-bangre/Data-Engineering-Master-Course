## STEP 1 — QUICK RECALL

### Recall Questions
1. What is the fundamental difference between DBMS and RDBMS?
2. Which category do `CREATE TABLE`, `INSERT INTO`, and `SELECT` belong to?
3. What happens when you insert a string longer than the defined `VARCHAR(N)` length?
4. How does SQL Server handle unspecified columns during an `INSERT INTO table (col1) VALUES (val1)` statement?

### Answers & Explanations
1. **DBMS vs RDBMS**: A DBMS manages flat files/data stores, whereas an RDBMS stores data in structured **tables (rows and columns)** connected via Primary Keys and Foreign Keys.
2. **Command Categories**:
   - `CREATE TABLE` $\rightarrow$ **DDL** (Data Definition Language)
   - `INSERT INTO` $\rightarrow$ **DML** (Data Manipulation Language)
   - `SELECT` $\rightarrow$ **DQL** (Data Query Language)
3. **String Truncation**: SQL Server throws a string truncation error ("String or binary data would be truncated") and terminates the insertion if string length exceeds $N$.
4. **Omitted Columns**: Omitted columns automatically receive `NULL` values if allowed, or their defined `DEFAULT` value.

## STEP 2 — CONCEPT UNDERSTANDING

### Topic 1: SQL Command Categories (DDL, DML, DQL, DCL, TCL)
- **What it means**: Classification of SQL queries based on their operational impact on schema structure vs table rows vs permissions.
- **Why/When used**:
  - **DDL** (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`): Modifies database schema/structure.
  - **DML** (`INSERT`, `UPDATE`, `DELETE`): Manipulates table rows/data.
  - **DQL** (`SELECT`): Reads and extracts data.
  - **DCL** (`GRANT`, `REVOKE`): Controls user permissions (handled by DBAs).
  - **TCL** (`COMMIT`, `ROLLBACK`): Manages transaction state.

### Topic 2: Data Types — `INT` vs `VARCHAR(N)` vs `TEXT`
- **What it means**: Storage specifications for columns.
- **Plain English Rules**:
  - Use `INT` for whole numbers.
  - Use `VARCHAR(N)` for short-to-medium text of known max length (variable length memory allocation).
  - Use `TEXT` (or `VARCHAR(MAX)`) for long descriptive entries.

### Topic 3: `NULL` vs Empty String (`''`)
- **What it means**: `NULL` represents the **absence of a value** (unknown/missing data). An empty string (`''`) is a **known, valid string of length 0**.
- **Crucial Rule**: `''` takes memory and represents a blank character value; `NULL` represents unknown data. Best practice in automation is to use `NULL` for missing data.

## STEP 3 — SQL SYNTAX & CODE EXAMPLES

### 1. Table Creation
```sql
CREATE TABLE StudentInfo
(
    roll_no   INT,
    name      VARCHAR(30),
    city      VARCHAR(30),
    subject   VARCHAR(15),
    marks     INT,
    email_id  VARCHAR(40)
);
```

### 2. Data Retrieval (DQL)
```sql
-- Retrieve all columns
SELECT * FROM StudentInfo;

-- Retrieve specific columns
SELECT name, city, marks FROM StudentInfo;
```

### 3. Data Insertion (DML)
```sql
-- All columns (Matching column sequence)
INSERT INTO StudentInfo VALUES (101, 'Arpit', 'Nagpur', 'Stat', 65, 'arpit@gmail.com');

-- Explicit Column List Insertion (Automation style)
INSERT INTO StudentInfo (roll_no, name, city) VALUES (102, 'Rahul', 'Pune');
```

## STEP 5 — COMMON MISTAKES & DEBUGGING

### Buggy Query 1
```sql
-- Bug: Omitted TABLE keyword in DDL statement
CREATE StudentInfo (roll_no INT, name VARCHAR(20));
```
- **Correction**: After DDL statements (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`), the `TABLE` keyword is mandatory.
```sql
CREATE TABLE StudentInfo (roll_no INT, name VARCHAR(20));
```

### Buggy Query 2
```sql
-- Bug: Inserting string without single quotes
INSERT INTO StudentInfo VALUES (101, Amit, HR, 2000);
```
- **Correction**: String/character values must always be enclosed in single quotes `'...'`.
```sql
INSERT INTO StudentInfo VALUES (101, 'Amit', 'HR', 2000);
```

## STEP 6 — REAL-WORLD DATA ENGINEERING APPLICATION

**Scenario**: You are configuring an automated ingestion pipeline that reads raw CSV files into an landing table.
- **Required Info**: Schema column names and maximum expected character lengths.
- **Approach**: Define the table schema using `CREATE TABLE` with explicit `VARCHAR(N)` limits matching target fields. Use column-specified `INSERT INTO table (col1, col2)` statements so missing raw fields default to `NULL` safely without breaking pipeline execution.

## STEP 7 — MINI ASSESSMENT

### Questions
1. Write a query to create a table `Employee` with `empid` (integer), `empname` (varchar 20), `dept` (varchar 20), `salary` (integer).
2. Write an `INSERT` statement inserting a row into `Employee` providing only `empid` and `empname`.
3. What value will be assigned to `dept` and `salary` for the row inserted in Question 2?

### Solutions
```sql
-- 1. Create Table
CREATE TABLE Employee (
    empid INT,
    empname VARCHAR(20),
    dept VARCHAR(20),
    salary INT
);

-- 2. Selective Column Insertion
INSERT INTO Employee (empid, empname) VALUES (108, 'Pushpak');

-- 3. Answer: `dept` and `salary` will be set to NULL.
```
