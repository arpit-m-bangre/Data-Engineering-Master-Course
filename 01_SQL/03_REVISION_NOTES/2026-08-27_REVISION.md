## 🧭 STEP 1: EXECUTIVE SUMMARY & VIVID REAL-LIFE ANALOGY

### 1. Executive Summary

In enterprise Data Engineering, writing queries is not merely about pulling rows; it is about solving complex analytical problems, detecting anomalies, calculating temporal growth metrics, and enforcing data integrity across multi-gigabyte transactional pipelines. This surprise assessment session consolidates all advanced SQL constructs mastered to date: **Value Window Functions (`LAG`/`LEAD`)**, **Ranking Functions (`DENSE_RANK`)**, **Common Table Expressions (CTEs)**, **Self Joins for Deduplication and Pairing**, **Date/Time Arithmetic (`DATEPART`, `DATEDIFF`, `DATEADD`)**, and **Aggregation Filters (`HAVING COUNT`)**.

### 2. The Vivid Real-Life Analogy: The High-Security Airport Terminal

Imagine managing security and passenger flow across a bustling international airport:

* **Tracking Salary Jumps (`LAG`):** Like checking a passenger's passport stamps sequentially. To see if someone suddenly jumped travel tiers by over 30% in baggage weight, the inspector compares their current ticket against their *immediately preceding* baggage slip.
* **Price Volatility (> 2 changes in 90 days):** Like airline ticket pricing algorithms. If an airline adjusted fuel surcharges multiple times within a 90-day rolling window, the auditor isolates only the price modification events and counts occurrences per flight route.
* **Customers Who Ordered Every Month (`COUNT(DISTINCT MONTH) = 12`):** Like the elite frequent flyer who boarded at least one flight in every single calendar month from January to December.
* **Fraud Detection (Simultaneous Multi-City Transactions):** Like airport security detecting that the same passenger's digital boarding pass was scanned at Delhi Airport Terminal 3 and Mumbai Airport Terminal 2 at the exact same minute (`10:45:00 AM`). Because a human cannot physically exist in two geographic locations simultaneously, this instantaneous collision flags an immediate red alert.

## 📖 STEP 2: TECHNICAL VOCABULARY & SIMPLE DEFINITIONS

| Technical Term | Simple Everyday English Meaning | Practical Example |
| :--- | :--- | :--- |
| **Inter-Row Peeking** | Looking backwards (`LAG`) or forwards (`LEAD`) at adjacent rows without collapsing data into groups. | `LAG(Salary) OVER (PARTITION BY EmpID ORDER BY SalaryDate)` |
| **Self Join** | Joining a table with a copy of itself to compare different rows within the same dataset. | `FROM BankTransactions t1 JOIN BankTransactions t2 ON t1.CustomerID = t2.CustomerID` |
| **Permutation Pruning** | Using `<` or `>` instead of `<>` in self joins so you only match pairs once `(A, B)` rather than both `(A, B)` and `(B, A)`. | `WHERE p1.ProductID < p2.ProductID` |
| **Temporal Granularity** | Slicing timestamps into specific time units like hour of the day, day of week, or calendar month. | `DATEPART(HOUR, OrderTime)` |
| **Rolling Window Filter** | Restricting analysis to a relative time window relative to an anchor date using date math. | `WHERE PriceDate >= DATEADD(DAY, -90, @AnchorDate)` |
| **Dense Ranking** | Ranking items where identical scores receive identical ranks without skipping subsequent rank numbers. | `DENSE_RANK() OVER (PARTITION BY CategoryID ORDER BY Revenue DESC)` |
| **Geo-Temporal Collision** | An anomaly where two events linked to the same entity occur at the same timestamp in distinct geographical locations. | `t1.TxnTime = t2.TxnTime AND t1.City <> t2.City` |

### 2. Architectural Comparison Matrix

| Problem Scenario | Primary Technical Technique | Secondary Clause / Filter | Key Gotcha / Pitfall |
| :--- | :--- | :--- | :--- |
| **Salary Jump > 30%** | `LAG(Salary) OVER (PARTITION BY EmpID ORDER BY Date)` | `WHERE Salary > PrevSalary * 1.30` | Forgetting `PrevSalary IS NOT NULL` (first recorded salary has no prior row). |
| **Price Volatility (>2 in 90 days)** | `LAG(Price)` in CTE | `WHERE Price <> PrevPrice` + `HAVING COUNT(*) > 2` | Counting unchanged price logs instead of true price changes (`Price <> PrevPrice`). |
| **Annual Active Customers** | `COUNT(DISTINCT MONTH(OrderDate))` | `GROUP BY CustomerID HAVING COUNT(DISTINCT ...) = 12` | Using `COUNT(MONTH)` instead of `COUNT(DISTINCT MONTH)` (multiple orders in 1 month). |
| **Identical Price Matching** | `Self Join (Products p1 JOIN Products p2)` | `ON p1.Price = p2.Price AND p1.ProductID < p2.ProductID` | Using `p1.ProductID <> p2.ProductID` generates duplicate mirror pairs `(A, B)` and `(B, A)`. |
| **Top 5 Spenders Overall** | `DENSE_RANK() OVER (ORDER BY SUM(Amount) DESC)` | `WHERE SpendRank <= 5` via CTE | Writing window function directly in `WHERE` clause (triggers SQL Server Error 4108). |
| **Peak Sales Hour** | `DATEPART(HOUR, OrderTime)` | `ORDER BY SUM(Amount) DESC` + `TOP 1` | Not grouping by `DATEPART(HOUR, OrderTime)`. |

| **Fraud Multi-City Collision** | `BankTransactions t1 JOIN BankTransactions t2` | `ON t1.CustID = t2.CustID AND t1.Time = t2.Time AND t1.City <> t2.City` | Matching the identical transaction row against itself (must include `t1.TxnID < t2.TxnID`). |

## 💻 STEP 4: PRACTICAL CODE BLUEPRINTS & T-SQL LAB

### Blueprint 1: Multi-Event Price Change Tracking within Rolling 90-Day Window

```sql
WITH PriceVarianceCTE AS
(
    SELECT 
        ProductID,
        ProductName,
        Price,
        PriceDate,
        LAG(Price) OVER (PARTITION BY ProductID ORDER BY PriceDate) AS PrevPrice
    FROM ProductPriceHistory
)
SELECT 
    ProductID,
    ProductName,
    COUNT(*) AS TotalPriceChangesIn90Days
FROM PriceVarianceCTE
WHERE Price <> PrevPrice 
  AND PriceDate >= DATEADD(DAY, -90, CAST('2026-08-27' AS DATE))
GROUP BY ProductID, ProductName
HAVING COUNT(*) > 2;
```

### Blueprint 2: Top Revenue Product per Category Pipeline

```sql
WITH CategoryRevenueRankCTE AS
(
    SELECT 
        p.CategoryID,
        p.ProductName,
        SUM(oi.Quantity * oi.Price) AS TotalCategoryRevenue,
        DENSE_RANK() OVER (
            PARTITION BY p.CategoryID 
            ORDER BY SUM(oi.Quantity * oi.Price) DESC
        ) AS RevenueRank
    FROM Products p
    JOIN OrderItems oi ON p.ProductID = oi.ProductID
    GROUP BY p.CategoryID, p.ProductID, p.ProductName
)
SELECT 
    CategoryID,
    ProductName,
    TotalCategoryRevenue
FROM CategoryRevenueRankCTE
WHERE RevenueRank = 1;
```

### Blueprint 3: Bank Fraud Detection Engine (Instantaneous Multi-City Collision)

```sql
SELECT 
    t1.CustomerID,
    t1.City AS CityOrigin,
    t2.City AS CityCollision,
    t1.TxnTime AS CollisionTimestamp,
```

## ⚙️ STEP 5: LOGICAL QUERY EXECUTION ORDER & SCOPING RULES

When writing analytical queries with CTEs, Aggregations, and Window Functions:

1. **`FROM` & `JOIN`:** The database engine builds the combined dataset.
2. **`WHERE`:** Non-aggregated row-level predicates filter the initial stream.
3. **`GROUP BY`:** Rows are collapsed into distinct key groups.
4. **`HAVING`:** Aggregate group metrics are filtered (e.g. `COUNT(DISTINCT MONTH) = 12`).
5. **`SELECT`:** Projections are computed.
6. **`WINDOW FUNCTIONS` (`OVER`):** Evaluated after grouping and projecting.
7. **`CTE WRAPPER` (`WHERE Rank <= 5`):** Outer query filters the window function results.
8. **`ORDER BY`:** Final result set is sorted for presentation.

## ⚠️ STEP 6: 10 BUG TRAPS & TIER-1 INTERVIEW SCENARIOS

1. **Bug Trap 1: Error 4108 Window Function in WHERE Clause**
   * *Problem:* `SELECT ... FROM T WHERE DENSE_RANK() OVER (...) = 1`.
   * *Fix:* Wrap query in a CTE or Derived Table and filter the computed alias in the outer `WHERE`.

2. **Bug Trap 2: Symmetrical Permutations in Self Joins**
   * *Problem:* `ON t1.Price = t2.Price AND t1.ID <> t2.ID` returns `(Product A, Product B)` and `(Product B, Product A)`.
   * *Fix:* Use strictly `t1.ID < t2.ID` to enforce single unique pair direction.

3. **Bug Trap 3: Null Comparison in LAG Percentage Calculation**
   * *Problem:* `WHERE Salary > LAG(...) * 1.3` fails to consider that the first row yields `NULL`, causing `Salary > NULL` to evaluate to `UNKNOWN`.
   * *Fix:* Always filter `WHERE PrevSalary IS NOT NULL AND Salary > PrevSalary * 1.30`.

4. **Bug Trap 4: Distinct Months vs Order Count**
   * *Problem:* `HAVING COUNT(MONTH(OrderDate)) = 12` incorrectly counts 12 orders placed in January alone.
   * *Fix:* Use `COUNT(DISTINCT MONTH(OrderDate)) = 12`.

5. **Bug Trap 5: Global Rank vs Partitioned Rank**
   * *Problem:* Forgetting `PARTITION BY CategoryID` in `DENSE_RANK()` returns only the single highest product across the entire company instead of per category.
   * *Fix:* Always verify partition boundaries: `DENSE_RANK() OVER (PARTITION BY CategoryID ORDER BY TotalRevenue DESC)`.

6. **Bug Trap 6: Multi-Year Month Collisions**
   * *Problem:* `MONTH('2025-01-10')` and `MONTH('2026-01-10')` both return `1`, causing cross-year data pollution.
   * *Fix:* Include year filtering: `WHERE YEAR(OrderDate) = 2026 GROUP BY CustomerID HAVING COUNT(DISTINCT MONTH(OrderDate)) = 12`.

7. **Bug Trap 7: Date Arithmetic Direction in Rolling Windows**
   * *Problem:* Using `DATEADD(DAY, 90, GETDATE())` instead of `-90` filters future dates instead of past 90 days.
   * *Fix:* Use `DATEADD(DAY, -90, GETDATE())` or `DATEDIFF(DAY, PriceDate, GETDATE()) BETWEEN 0 AND 90`.

8. **Bug Trap 8: Price Change Detection Counting Repeat Logs**
   * *Problem:* Simply counting rows within 90 days rather than counting actual price differences (`Price <> PrevPrice`).
   * *Fix:* Filter `WHERE Price <> PrevPrice` inside the outer query before applying `COUNT(*)`.

9. **Bug Trap 9: Self-Collision in Fraud Detection**
   * *Problem:* `ON t1.CustomerID = t2.CustomerID AND t1.TxnTime = t2.TxnTime` matches transaction 101 with transaction 101 itself.
   * *Fix:* Include `t1.TxnID < t2.TxnID` along with `t1.City <> t2.City`.

10. **Bug Trap 10: Aggregating Pre-Ranked vs Post-Ranked Quantities**
    * *Problem:* Trying to run `DENSE_RANK() OVER (ORDER BY Quantity * Price DESC)` inside an unaggregated table when multiple order items exist for the same product.
    * *Fix:* Group by `ProductID, CategoryID` and rank by `SUM(Quantity * Price)`.

## 🎯 STEP 7: SELF-ASSESSMENT FLASHCARDS & REVISION DRILLS

### Flashcards

* **Q1: Why is a CTE required when filtering by `DENSE_RANK()` or `ROW_NUMBER()`?**
  * *Answer:* Because SQL evaluates the `WHERE` clause at Step 2 before Window Functions are computed at Step 6. A CTE materializes the ranked output so the outer `WHERE` can filter on the calculated rank alias.

* **Q2: In a self join for duplicate detection, what is the exact difference between `t1.ID <> t2.ID` and `t1.ID < t2.ID`?**
  * *Answer:* `<>` produces double entries (symmetrical pairs like A-B and B-A), whereas `<` prunes mirror permutations, guaranteeing each pair appears exactly once.

* **Q3: What does `LAG(col, 1, 0) OVER (...)` do when evaluated on the first row of a partition?**
  * *Answer:* Instead of returning the default `NULL` for the non-existent previous row, it substitutes the custom fallback default value `0`.

* **Q4: How do you detect an employee whose sales rank #1 in each separate calendar month?**
  * *Answer:* Group sales by `MONTH(SaleDate)` and `EmpID`, compute `DENSE_RANK() OVER (PARTITION BY MONTH(SaleDate) ORDER BY SUM(Amount) DESC)`, and filter `WHERE MonthlyRank = 1` inside a CTE.
