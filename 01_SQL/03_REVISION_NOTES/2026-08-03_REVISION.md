## 🧠 STEP 1 — QUICK RECALL

### ❓ Recall Questions
1. Does `SELECT DISTINCT dept` physically delete duplicate rows from the database?
2. If you write `WHERE A OR B AND C`, which part does SQL calculate first?
3. What is the wildcard pattern to find a name with exactly 5 characters starting with 'M'?
4. How do you find an employee whose name contains an 'a' in the second position and an 'i' in the second-to-last position?

### 🗝️ Answers & Explanations
1. **`DISTINCT` Behavior**: No! `DISTINCT` is just a pair of magic glasses. It visually hides the duplicates on your screen, but the actual data in the database remains untouched.
2. **Operator Precedence (The Math Order)**: SQL processes `AND` before `OR` (just like multiplication happens before addition in math). It evaluates `(B AND C)` first, then checks `A OR (result)`. To override this, wrap your logic in parentheses!
3. **Exact Length Wildcard**: `LIKE 'M____'` (That's M followed by exactly 4 underscores).
4. **Specific Position Wildcard**: `LIKE '_a%i_'`.

## 🧠 STEP 2 — CONCEPT UNDERSTANDING

### Topic 1: The `DISTINCT` Filter (The Bouncer's Guest List)
- **What it means**: Imagine a bouncer looking at a massive crowd where people are wearing identical shirts. The bouncer only writes down each color once. `DISTINCT` filters the view so you only see unique items!
- **Plain English Rule**: `DISTINCT` applies to the *entire row combination* you ask for. If you ask for `DISTINCT First_Name, Last_Name`, it looks for unique pairs of names, not just unique first names.

### Topic 2: Operator Precedence & Parentheses (The Traffic Cop)
- **What it means**: When you shout complex orders at SQL ("Give me IT people OR HR people AND salary over 5000!"), SQL might misunderstand you. Parentheses `()` act like a traffic cop, telling SQL exactly what to process first.
- **Why/When used**: ALWAYS use parentheses when mixing `AND` with `OR` to prevent disastrous logical bugs.

## 📖 STEP 2.5 — VOCABULARY & DEFINITIONS

- **DISTINCT**: Unique, non-repeated. It means "show me only one of each kind."
- **Precedence**: The order of importance or calculation (e.g., `AND` is calculated before `OR`).
- **Deduplication**: The process of removing or hiding duplicate records to see only unique values.
- **Alias**: Giving a temporary nickname to a column or table (like calling `employee1` just `e`).

## 💻 STEP 3 — SQL SYNTAX & CODE EXAMPLES

### 1. DISTINCT Keyword Usage
```sql
-- Example A: Find all unique departments (The Bouncer's List)
SELECT DISTINCT dept FROM employee1;

-- Example B: Multi-column distinct combos
SELECT DISTINCT dept, city FROM employee1; 
-- Returns unique pairs (e.g., "HR - Pune" is different from "HR - Mumbai")

-- Example C: Combining DISTINCT with WHERE (New!)
SELECT DISTINCT city FROM employee1 WHERE salary > 50000;
-- "Show me the unique cities where our high earners live."
```

### 2. Multi-Condition Logic (Using the Traffic Cop)
```sql
-- Example A: Safe grouping with Parentheses
SELECT * FROM employee1 
WHERE (dept = 'HR' OR dept = 'Entc') AND salary > 5000;
-- Gets HR or Entc employees, but ONLY if they make over 5000.

-- Example B: DANGEROUS Logic without Parentheses!
SELECT * FROM employee1 
WHERE dept = 'HR' OR dept = 'Entc' AND salary > 5000;
-- Buggy! Because AND runs first, it actually means:
-- "Give me ALL HR people regardless of salary, PLUS Entc people who make over 5000."

-- Example C: Super complex conditional search (New!)
SELECT * FROM employee1
WHERE (city = 'Pune' AND dept = 'IT') OR (city = 'Mumbai' AND dept = 'Finance');
```

### 3. Advanced LIKE Parsing
```sql
-- Example A: Multi-character positions
SELECT * FROM employee1 WHERE empname LIKE '_a%i_'; 
-- 1st is anything, 2nd is 'a', middle is anything, 2nd-to-last is 'i', last is anything.

-- Example B: Exact length limits
SELECT * FROM employee1 WHERE empname LIKE '_____'; -- Exactly 5 letters long!

-- Example C: Excluding letters at specific positions (New!)
SELECT * FROM employee1 WHERE empname LIKE '[^A-E]%_'; 
-- Does NOT start with A, B, C, D, or E!

-- Example D: Finding specifically formatted data like IDs (New!)
SELECT * FROM employee1 WHERE EmployeeID LIKE 'EMP-[0-9][0-9][0-9]'; 
-- Finds IDs formatted exactly like "EMP-123".
```

## ⚠️ STEP 5 — COMMON MISTAKES & DEBUGGING

### Mistake 1: Placing DISTINCT on multiple separate columns
```sql
-- ❌ BUGGY LOGIC: Thinking DISTINCT only applies to the first column
SELECT DISTINCT name, salary FROM employee1;
```
- **✔️ CORRECTION**: `DISTINCT` cannot apply to just one column if you ask for two! It evaluates the **entire row** combination. If two people are named 'Arpit' but have different salaries, BOTH will be shown because the *combination* is unique!

### Mistake 2: Missing Parentheses around OR
```sql
-- ❌ BUGGY QUERY: Mixing OR and AND without parentheses
SELECT * FROM employee1 WHERE city = 'Pune' OR city = 'Mumbai' AND salary > 10000;
```
- **✔️ CORRECTION**: Always wrap your `OR` statements in parentheses to force SQL to evaluate them as a group first!
```sql
SELECT * FROM employee1 WHERE (city = 'Pune' OR city = 'Mumbai') AND salary > 10000;
```
