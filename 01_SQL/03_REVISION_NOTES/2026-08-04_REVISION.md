## STEP 1 — QUICK RECALL

### Recall Questions
1. Do temporary alias columns created in a `SELECT` query alter the physical table schema?
2. What is the fundamental difference between `DELETE FROM table` vs `DROP TABLE table`?
3. What happens if you execute `UPDATE StudentInfo SET subject = 'Maths'` without a `WHERE` clause?
4. Can empty strings (`''`) be assigned to numeric integer columns during an `UPDATE` operation?

### Answers & Explanations
1. **Computed Columns**: No. Output calculation columns exist **only in query results**; physical table schema remains unchanged.
2. **`DELETE` vs `DROP`**: `DELETE` removes table **data rows** (structure stays); `DROP` deletes the **entire table structure AND data**.
3. **Unconditional `UPDATE`**: It updates **every single row** in the table!
4. **Empty Strings & Numeric Types**: No. Assigning `''` to an `INT` column converts `''` to `0` or throws an invalid type conversion error. `NULL` should be used for numeric missing data.

## STEP 2 — CONCEPT UNDERSTANDING

### Topic 1: Computed Alias Columns
- **What it means**: Performing inline mathematical operations during `SELECT` projections.
- **Example**: `SELECT *, NewSalary = salary * 1.10 FROM employee1;`

### Topic 2: `DELETE` vs `UPDATE` Rules
- **`DELETE`**: DML command to remove specific rows matching a `WHERE` condition.
- **`UPDATE`**: DML command to modify column values in existing rows matching a `WHERE` condition.
- **Crucial Rule**: Always test your `WHERE` clause with `SELECT` *before* executing `UPDATE` or `DELETE` to avoid unintended data loss.

## STEP 3 — SQL SYNTAX & CODE EXAMPLES

```sql
-- 1. Computed Projection Columns
SELECT *,
       New_marks  = marks + 10,
       Inc_salary = salary * 1.10
FROM StudentInfo;

-- 2. DELETE Statement
DELETE FROM employee1 WHERE empid = 101;

-- 3. UPDATE Statement (Single & Multiple Columns)
UPDATE StudentInfo
SET subject = 'Maths'
WHERE name LIKE '%i%';

UPDATE StudentInfo
SET subject = 'Art', marks = 90, age = 23
WHERE mobile_no = 992342352;

-- 4. DROP Table
DROP TABLE employee1;
```

## STEP 5 — COMMON MISTAKES & DEBUGGING

### Buggy Query 1
```sql
-- Bug: Accidental UPDATE of all rows due to missing WHERE clause
UPDATE StudentInfo SET subject = 'Physics';
```
- **Correction**: If you only intended to update physics students, append `WHERE`.
```sql
UPDATE StudentInfo SET subject = 'Physics' WHERE roll_no = 101;
```

### Buggy Query 2
```sql
-- Bug: Attempting to check NULL with = NULL in UPDATE
UPDATE StudentInfo SET city = 'Nashik' WHERE city = NULL;
```
- **Correction**: Use `IS NULL` instead of `= NULL`.
```sql
UPDATE StudentInfo SET city = 'Nashik' WHERE city IS NULL;
```

## STEP 6 — REAL-WORLD DATA ENGINEERING APPLICATION

**Scenario**: Annual salary increment pipeline adjusting employee pay based on department performance.
- **Required Info**: Employee department and performance metrics.
- **Approach**: Execute `UPDATE` with arithmetic expressions scoped via `WHERE`:
```sql
UPDATE StaffPayroll 
SET BaseSalary = BaseSalary * 1.12 
WHERE DeptCode = 'IT' AND PerformanceScore >= 4;
```
